# 实时变声器产品需求文档

版本：0.2 | 日期：2026-10-24 | 状态：核心范围已确认；硬件与量化指标待验证，完整基线未冻结

实施补充（2026-10-25）：用户要求直接实现初版并通过个人 GitHub `GoesM/voice_changer` 管理及发布。已进入 v0.1.0 技术预览实现；采用本地 Beatrice VST3 宿主和用户安装的 VB-CABLE，详见 ADR-001。原量化目标保留，不因预览交付而视为达标。

## 1. 问题与目标

用户希望在电脑上使用变声后的麦克风声音，并能用于多个现有应用，不需要逐个开发应用插件。

已确认：做一个电脑变声器产品；优先对齐需求、评估可行性；采用规范的需求→开发→落地管理路线。

本轮用户确认：

| 事项 | 已确认要求 |
| --- | --- |
| 首发系统 | Windows 11 |
| 核心效果 | 自然 AI 音色转换，首版男声转自然女声 |
| 接入体验 | 首次设置系统默认虚拟麦克风，个别应用选择一次输入；此后日常直接使用 |
| 优先场景 | 腾讯会议、瓦洛兰特游戏语音 |
| 音频处理 | 必须在本机离线执行，不依赖云端推理 |
| 模型获取 | 允许联网下载模型 |
| 交付定位 | 准备向其他用户发布；是否收费及开源方式尚未决定 |

原始技术设想：在实体麦克风接收声音之后、目标应用读取音频之前执行变声。评估：方向成立，建议通过独立变声引擎和虚拟录音设备实现。

产品目标表述：Windows 11 用户完成一次输入设备配置后，通过本地 AI 将男声实时转换为自然女声，经虚拟麦克风供会议、游戏等应用使用。稳定性、清晰度、自然度和延迟的量化标准按第 6 节验证后冻结。

## 2. 定义与承诺边界

- “电脑通用”分为跨应用兼容与跨操作系统支持，二者分别验收。
- “跨应用”指支持标准系统录音设备、允许选择虚拟麦克风或遵循系统默认输入的应用。首版只承诺实测兼容矩阵内的应用与版本。
- 设置默认录音设备不保证覆盖固定选择实体麦克风、已打开旧音频流或限制虚拟设备的应用。
- 首版“变声”明确为男声转自然女声的 AI 音色转换；单纯升调、机器人等特效不能替代核心需求。
- 不承诺隐藏实体麦克风、强制接管所有应用、绝对不可辨识、零延迟或任何硬件均能运行高质量 AI。

## 3. 用户与核心流程

首发用户：在 Windows 11 上使用会议和游戏语音、愿意完成首次输入配置的用户。以腾讯会议、瓦洛兰特作为首批验证场景，面向外部用户分发。

首次流程：安装并检查设备组件 → 下载并校验模型 → 授予麦克风权限 → 选择实体输入 → 选择女声音色 → 耳机试听 → 设置系统默认录音/通信输入并按需配置目标应用 → 测试通话。

日常流程：启动 → 恢复上次有效配置 → 明确显示就绪状态 → 开始变声 → 切换音色/静音 → 停止。

异常流程：输入丢失、模型失败或处理过载 → 显示原因 → 虚拟输出静音 → 引导恢复。不得默认回退输出原声；此项为建议策略，待确认。它只能约束本产品输出，不能阻止第三方应用自行切回实体麦克风。

## 4. 范围建议

首发系统确定为 Windows 11；x64 为建议架构，准确系统版本和硬件基线在验证前锁定。macOS/Linux 不进入首版。

首版候选范围：单路麦克风、本地 AI 男声转女声、虚拟麦克风、模型下载与管理、试听、静音、状态诊断、安装卸载与故障恢复。建议至少一个可分发的自然女声预设；数量和风格待音质验证。

暂不纳入首版建议：任意人物声音克隆、模型训练平台、音色商城、账号付费、移动端、多人混音、专业 ASIO 工作流。若用户提出，应重新评估范围。

## 5. 功能需求与验收

以下优先级和默认行为均为提案；P0 为候选发布必需，P1 为后续增强。

| ID | 优先级 | 需求 | 验收条件 |
| --- | --- | --- | --- |
| FR-001 | P0 | 输入设备管理 | 列出可用实体输入，选择后显示电平；无权限、设备占用或拔出时提供明确状态；禁止将自身虚拟输出选为输入形成回路 |
| FR-002 | P0 | 本地 AI 男声转女声 | 持续转换男声为自然女声，保留语句内容；自然度和清晰度通过 NFR-003；无云端推理；具体预设数量和调节参数待冻结 |
| FR-003 | P0 | 虚拟麦克风 | 安装后能被系统和目标应用枚举；目标应用录到处理后的声音；必须通过目标应用实际录音/通话验证 |
| FR-004 | P0 | 首次配置与日常复用 | 引导设置系统默认录音/通信输入，必要时在应用内选择虚拟麦克风；腾讯会议和瓦洛兰特在应用及系统重启后复测，无设备变化时无需重复配置；设置被外部改变时提供排查方法 |
| FR-005 | P0 | 状态与静音 | 明确区分停止、加载、变声、静音、故障；静音时虚拟输出无语音；原声旁路若提供，必须由用户显式启用并持续提示 |
| FR-006 | P0 | 本地试听 | 用户可选择耳机输出、单独关闭监听；默认不监听，避免扬声器回授；试听不改变目标应用输入选择 |
| FR-007 | P0 | 故障处理 | 模型失败、进程退出、输入拔出、过载时不由本产品输出未处理原声；过载不无限累积队列；恢复后状态正确 |
| FR-008 | P0 | 配置保存 | 保存输入、效果、参数；设备消失时不静默切到未知麦克风；启动后清晰提示是否正在采集 |
| FR-009 | P0 | 安装与卸载 | 普通用户按向导完成安装；提权需求可解释；发布包可在受支持系统正常安全配置下安装；卸载移除本产品组件并验证音频可恢复 |
| FR-010 | P0 | 诊断 | 导出版本、设备、错误、处理耗时和缓冲统计；默认不记录音频；导出前展示内容范围 |
| FR-011 | P1 | 快捷键与托盘 | 静音和预设切换可配置，冲突可提示；最小化后仍明确状态 |
| FR-012 | P0 | 模型获取与离线加载 | 显示模型大小、版本和下载进度；校验完整性；下载中断可重试，损坏模型不加载；已安装模型断网后可冷启动并持续变声；下载失败不影响已有可用模型 |

## 6. 非功能目标及测量口径

以下数字是待验证的产品目标，不是现有性能或已确认承诺。硬件基线、模型、输入设备、系统版本与负载未锁定前，不作达标结论。

| ID | 指标 | 候选验收方式 |
| --- | --- | --- |
| NFR-001 | 本地链路延迟 | AI 档候选 p95 ≤ 150 ms；经 PoC 和会议/游戏试用验证后冻结；至少 100 次有效测量，报告 p50/p95/最大值；不能以牺牲自然女声目标的 DSP 效果代替达标 |
| NFR-002 | 稳定性 | 选定硬件和每个首发目标应用连续 2 小时，无崩溃、无超过 100 ms 的非预期断音、无持续增长的排队延迟；记录全部欠载/溢出事件 |
| NFR-003 | 音质 | 固定中文语料覆盖长句、轻声、爆破音、笑声、噪声和多位男声说话者；建议 5 名评测者盲听，清晰度均分 ≥ 4/5、自然度均分 ≥ 3.5/5，至少 80% 有效评价认为符合目标女声音色；量表与样本规模需冻结 |
| NFR-004 | 资源 | 测量空载、变声、同时运行目标应用下 CPU/GPU/内存/显存；硬上限和最低配置经 PoC 后填写，未填写不可宣称低配兼容 |
| NFR-005 | 恢复 | 测试设备拔插、睡眠唤醒、默认设备变化、模型失败和进程退出；恢复时间候选 ≤ 5 秒（模型重新加载单独计时），不得泄露原声 |
| NFR-006 | 离线音频处理（已确认） | 模型安装后断网冷启动、转换、切换已安装音色和本地录音均可用；本产品不向外发送原始音频、处理后音频或声学特征，不调用云端推理；默认不存储音频为建议策略。会议/游戏自身的语音联网传输不属于本产品离线约束 |
| NFR-007 | 易用性 | 建议 5 名首次使用者中至少 4 名无需工程师帮助完成配置和测试通话；单独记录安装、下载和配置耗时 |

延迟分解：硬件/采集缓冲 + 分帧及模型前瞻 + 推理 + 重采样/队列 + 虚拟设备输出缓冲。测量从实体输入到测试客户端读取虚拟录音流，使用可校准的测试信号/回环方法；AI 改变波形时需采用事件标记或可解释的对齐方法。目标应用内部降噪、编码、网络及远端播放延迟单独报告，不计入上述本地阈值。模型单次推理耗时不等于完整延迟。

## 8. 需求冻结前需回答

1. 目标硬件覆盖：先支持有独显的电脑，还是必须覆盖无独显电脑？准确基线与资源上限由实测确定；当前尝试读取本机硬件被环境拒绝，未获得配置。
2. 用户可接受的安装提权与重启体验；首次应用输入配置已经确认可接受，无需重复询问。
3. 自然度与延迟的取舍、具体女声风格；建议采用第 6 节候选指标先验证，保留失败时重新评估的决策点。
4. 故障静音、默认不存储音频为当前建议；需要在完整需求基线中确认。
5. 公开发布的收费/开源方式、预算、期望周期和维护资源；发布意图已经确认，不等同于已确认商业收费。
6. 两应用同时使用是否属于首版必需；Windows 11 的版本、架构和游戏发行区服在验证计划中锁定。

## 9. 发布准入

首版范围与指标得到确认；P0 需求关联验收证据；兼容矩阵必测项通过；无阻断缺陷；安装升级卸载可复现；依赖、模型及音色来源和分发许可清单完成；提供使用说明、已知问题、版本说明与恢复方法。

公开发布必须提供：最低/推荐配置、支持系统和应用版本、模型下载及校验清单、驱动和模型分发依据、离线行为说明、安装/升级/卸载恢复步骤。瓦洛兰特在正常游戏和反作弊环境中测试，不以关闭反作弊或系统安全功能作为兼容方案。具体验收步骤见 [验收计划](ACCEPTANCE.md)。
